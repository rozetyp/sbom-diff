# Tests

- `core.test.mjs`: logic tests (Node, no browser): every scenario in `expected.json` plus regression cases.
- `e2e.test.mjs`: browser tests that drive the real page in headless Chromium.
- `load-core.mjs`, `serve.mjs`: helpers (load the compiled `core.js`; a tiny static server, also used by `npm start`).

## Fixtures

`fixtures/` holds the test SBOMs. `expected.json` is the ground truth: each scenario names its file(s), what should load, which components each license policy flags, what the diff should show, or which error should appear. The expectations were written by hand from the SBOM contents, not generated by the app.

`core.test.mjs` runs every scenario and fails if any file in `fixtures/` is not covered by one. To add a case, drop the SBOM in `fixtures/` and add a scenario.

| File | What it exercises |
|---|---|
| `cdx-pass.json` | Permissive licenses only: every policy passes |
| `cdx-fail.json` | One component each under GPL, AGPL, LGPL, SSPL, plus one MIT |
| `cdx-a.json`, `cdx-b.json` | Basic diff: one added, one removed, one version change |
| `spdx-b.json` | SPDX counterpart to `cdx-b.json`, for cross-format diffs against `cdx-a.json` |
| `cdx-large-a.json`, `cdx-large-b.json` | 81 vs 82 components: list truncation in the UI |
| `cdx-multiversion-a.json`, `-b.json` | Two versions of one package in the same SBOM |
| `cdx-dupes.json` | Same purl at two versions |
| `cdx-nested.json` | Nested CycloneDX components |
| `cdx-dual-license.json` | License expressions: OR, AND, `+`, lowercase operators, nesting |
| `cdx-expression.json` | `GPL-3.0-only WITH Classpath-exception-2.0` |
| `cdx-missing.json` | Components without version or license |
| `not-sbom.json`, `invalid.json`, `spdx3.json`, `cdx.xml` | Inputs that must be rejected with a clear message |
